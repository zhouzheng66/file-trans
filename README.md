# File Trans · 轻传

在自己的电脑之间传输文件和文字的桌面工具。无需账号；首次双端核对配对，之后记住设备。

当前已实现前四个阶段：**Windows/macOS/Linux 桌面客户端、局域网发现与直传、跨互联网加密中继、双端配对、文字与任意格式文件传输、已配对设备自动接收、完整性校验、文件断点续传、暂停恢复、传输中切换通道和保留目录结构的文件夹传输**。

安装包见 [GitHub Releases](https://github.com/zhouzheng66/file-trans/releases)。提供 Windows x64、macOS Apple 芯片/Intel、Linux x64，选择方法和发布流程见[安装与发布](docs/安装与发布.md)。

默认自动优先局域网，局域网不可达时回退互联网中继，也可手动选择仅局域网或仅互联网。跨网使用前需在两端配置同一个已部署的 `wss://` 中继，参见[中继部署](docs/中继部署.md)。双方需要同时打开客户端；离线暂存尚未实现。

## 开发启动

需要 Node.js 22+、npm、Rust stable，以及平台的 Tauri 编译依赖：macOS 使用 Xcode 命令行工具；Windows 使用 Visual Studio C++ Build Tools 和 WebView2。详见 [Tauri 环境准备](https://v2.tauri.app/start/prerequisites/)。

```bash
npm install
npm run dev
```

如果项目已有 `.tooling/cargo` 工具链，脚本优先使用该工具链，否则使用系统 Rust；不会修改系统配置。

```bash
npm run check          # TypeScript 检查
npm run build          # 前端构建
npm run test:core      # 协议、文件处理和两节点 TCP/TLS 集成测试
npm run test:ui        # 外部拖拽路径分发与逐项错误测试
npm run check:rust     # 包括 Tauri 的完整 Rust 编译检查
npm run lint:rust      # Rust 静态检查
npm run fmt           # Rust 格式化
npm run desktop:build # 当前平台的桌面程序和安装包
npm run relay         # 启动本机中继服务，默认 127.0.0.1:8787
```

编译输出位于根目录 `target/`。在 macOS 构建不能替代 Windows 原生构建；未签名安装包仅适合开发验证。

## 局域网使用步骤

1. 两端运行客户端，连接同一可互访的局域网；按系统提示允许本地网络和防火墙访问。
2. 在“附近的设备”点击对方。若没有自动发现，在“我的设备”右侧点 `+`，输入对方侧边栏显示的 `IP:端口`。
3. 核对两端的八位安全校验码一致，两端分别确认。不要仅根据设备名称确认。
4. 选择已配对电脑发送文字（Enter 发送，Shift + Enter 换行），或选择文件、文件夹，也可从系统文件管理器直接拖入（支持混合多选）。接收方自动接收，无需逐个确认。
5. 接收文件默认保存在下载目录的 `File Trans` 文件夹，可点击窗口底部的“修改目录”更改，重启后继续使用。新任务使用新目录，已有任务保留原位置；重名内容自动加序号，不覆盖已有文件。
6. 文件或文件夹接收完成后，点击“打开所在位置”，在 Finder / 文件管理器中定位接收内容。

同名、无扩展名、零字节和任意格式文件都走二进制传输。不同系统的非法文件名会进行安全处理。单文件当前协议上限为 8 TiB，实际还受磁盘与文件系统限制。

自动发现使用 IPv4 mDNS；手动连接也使用客户端当前显示的 IPv4 地址。访客 Wi-Fi、跨 VLAN、VPN 或禁止组播的网络可能需要调整网络设置。端口由系统自动分配，重启后应以界面显示值为准。

## 文件夹与外部拖拽

先选择已配对电脑，点击“选择文件夹”，或从 Finder / Windows 文件资源管理器把文件、文件夹直接拖到应用窗口。每个顶层目录对应一个可暂停、续传和切换通道的任务，保留子目录、空目录、零字节文件和中文名称；同名接收目录追加序号，不合并或覆盖。一次最多添加 128 项，失败项会显示原因。

文件夹先在发送端生成稳定快照，再开始网络传输。快照准备好后，原目录变化不影响该任务；准备中发生变化则报错。发送端额外需要约一份目录内容的磁盘空间，接收端在展开时约需两份。进度包含目录清单开销；不压缩，不保留权限、扩展属性和链接关系。

两端均需升级到第四阶段客户端。不支持符号链接、Windows 重解析点、特殊文件、跨平台不安全名称及大小写冲突；遇到这些条目会明确报错。清单最多 16 MiB、100,000 项、64 层，相对路径最长 1,024 字节，快照最多 8 TiB。见[第四阶段设计](docs/第四阶段设计.md)。

## 跨互联网与网络模式

两端在“互联网设置与跨网配对”保存相同中继地址并等待连接；一端生成五分钟配对码，另一端输入，之后仍需双方核对安全校验码并确认。已配对设备此后可直接选择发送。

顶部可切换自动、仅局域网、仅互联网中继三种模式，选择会保存到本机。进行中的文件会保存断点、重新选路并继续传输；文字与配对使用新连接时的模式。自动模式也会在局域网恢复可达后将中继文件任务切回直连。每条记录显示实际通道；仅局域网不会回退公网，仅互联网也不会偷偷使用直连。没有配置中继时，自动模式仍可局域网使用，跨网连接会给出配置提示。

中继只转发设备间 TLS 密文，不保存文件。互联网传输受服务端流量和时长配额限制，默认单隧道双向总流量约 16 GiB、最长两小时，可由服务管理员调整。

## 断点续传与暂停

文件和文件夹任务可在任一端暂停、恢复或取消；双方都暂停时，需要双方分别恢复。断网、中继重启或应用重启后，未主动暂停的任务会自动接续。自动接收不取消用户的暂停、取消或拒绝状态。

续传先校验本地已保存前缀，只通过网络发送剩余内容。普通文件的发送源文件必须保留在原路径且内容不变；文件夹使用准备好的本机快照，缓存须保留。接收临时文件也不能删除或修改。文件变化或断点损坏会明确报错，处理后可恢复或取消重发。修改默认接收目录不会迁移已有任务。

新文件协议要求双方都更新到第三阶段客户端；旧版文字、配对和传入文件仍兼容。详见[第三阶段设计](docs/第三阶段设计.md)与[第三阶段验收](docs/第三阶段验收.md)。

## 数据与身份

- 设备私钥存放在 macOS Keychain / Windows Credential Manager，不写入 SQLite 或前端。
- Linux 设备私钥存放在会话 Secret Service（例如 GNOME Keyring），需要已解锁的凭据库，不回退为明文文件。
- 公共设备证书、可信设备和本机收发历史存放在应用数据目录。
- 系统凭据库不可用时启动会明确失败，不自动更换身份。
- 配对完成后按证书指纹识别设备。移除信任后，对方的后续连接不能发送文字或文件。
- 文件断点、接收授权和暂停状态存入 SQLite；未完成数据保存在接收目录的隐藏子目录。断网或退出应用会保留断点，取消任务清理受管理的临时文件。

可通过环境变量为本机多实例验证指定独立配置：`FILE_TRANS_DATA_DIR`、`FILE_TRANS_DOWNLOAD_DIR`、`FILE_TRANS_DEVICE_NAME`。每个实例的应用数据目录必须不同。
