## 桌面入口

桌面新增“选择文件夹”，并以 Tauri 原生路径事件接收外部拖拽。文件选择与混合拖拽共用 `send_path` 后端，统一判断普通文件或文件夹；不再静默只处理前四个路径。一次最多添加 128 项，错误逐项汇总。未选择已配对电脑时提示先选择设备。

`npm run test:ui` 使用 Node 自带测试器验证混合拖拽的路径分发：超过四项的列表全部进入同一后端入口，重复路径去重，单项错误不丢弃后续项，并显示失败路径。这不替代系统拖拽实测。

用户处理系统钥匙串提示后，更新后的 macOS 客户端已正常启动。已实际使用原生“选择文件夹”对话框发送目录；用户在 Finder 手动拖入测试文件与文件夹后，应用产生对应任务，接收节点均确认完成。

接收结果按目录树及文件 SHA-256 比对：272 字节目录快照还原中文文本、零字节文件与嵌套空目录（共 4 个条目），与源目录一致；同名第二份目录另存为带序号目录。256 KiB 二进制样例为 262,144 字节，SHA-256 为 `2312394bd99545d9de131c24efb781e765ac1aec243f2ed9347597a793a415e9`，与源文件一致，无残留 `.part`。

Finder 的实际拖拽由用户完成，自动操作工具的跨窗口鼠标定位报 `windowNotFoundAtPosition`；用户完成操作后，工具读取真实任务和接收文件核验，没有用模拟路径分发测试替代系统拖拽。

混合多选实测中，同时选中文件与文件夹拖入后，新增两个 UUID 不同的任务，创建时间相差 1 毫秒，均显示经互联网中继完成。最终累计三份样例目录、两份样例二进制文件（包括选择器与重复拖入任务），目录树和文件 SHA-256 全部与源样例一致；同名项另存带序号的副本，无残留 `.part`。
