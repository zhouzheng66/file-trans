# File Trans 设计文档

> v0.2.2 更新：桌面客户端对已配对设备自动接收文件与文件夹，不再逐项确认；支持 Enter 发送、修改接收目录及在文件管理器中定位接收内容。最新交互见[收发交互设计](收发交互设计.md)，下文涉及逐项接收确认的内容保留为阶段历史。

本文保留第一阶段的基础设计。第二阶段已增加互联网中继与三种网络模式，第三阶段已增加文件断点续传、暂停恢复与传输中通道迁移，第四阶段已增加文件夹目录快照与系统外部拖拽。当前实现以[第二阶段设计](第二阶段设计.md)、[第三阶段设计](第三阶段设计.md)、[第四阶段设计](第四阶段设计.md)和[中继部署](中继部署.md)为补充；下文的阶段范围与失败处理描述保留为历史设计，最新文件与文件夹行为以对应阶段文档为准。

## 1. 产品目标与范围

在自己的 Windows、macOS 电脑之间传送文字与任意格式文件。无需账号，首次确认配对后记住设备；局域网优先直连，未来支持跨互联网与手动切换。

第一阶段交付原生桌面客户端、局域网发现、双端确认配对、文字传输、接收确认、流式文件传输与完整性校验。双方必须在线。跨互联网、断点续传、传输中的通道迁移、文件夹和剪贴板自动同步不属于第一阶段。界面不能将尚未实现的模式显示为可用。

## 2. 技术路线

- 桌面：Tauri 2、React、TypeScript、Vite。
- 核心：Rust、Tokio；所有文件数据在 Rust 中读写和传输，不经过前端 IPC。
- 发现：mDNS/DNS-SD，服务类型 `_filetrans._tcp.local.`；支持手动输入 `IP:端口`。
- 局域网通道：TCP 上的双向 TLS 1.3，使用 rustls。
- 本地存储：SQLite 保存可信设备、消息和任务记录；操作系统凭据库保存设备私钥，应用数据目录仅保存公开证书。
- 未来公网：客户端主动连接 WSS 中继，中继转发内层端到端 TLS 字节流。进一步评估跨网 P2P，保留中继兜底。

## 3. 模块边界

```text
apps/desktop/src             界面与桌面 IPC 适配
apps/desktop/src-tauri       启动、命令、原生能力与生命周期
crates/protocol              版本化消息、长度限制和二进制帧
crates/identity              证书、私钥、TLS 与安全校验码
crates/discovery             本地服务发布、发现与过期处理
crates/core                  配对、路由、传输、持久化与运行状态
```

第一阶段将传输、持久化等职责拆为 core 内的独立模块，避免创建只有转发作用的空 crate。复杂度增长后可继续拆分。协议与引擎均可脱离 Tauri 测试。

## 4. 设备身份与配对

1. 首次启动生成自签名设备证书与私钥。证书 SHA-256 指纹作为设备 ID，设备名称仅供展示。
2. 私钥通过系统凭据库持久化；身份读取失败时明确报错，不静默替换设备身份。
3. mDNS 广播名称、协议版本、端口和设备 ID，不广播密钥或历史记录。广播只表示候选地址，不构成信任。
4. 未配对设备仅能发起配对。TLS 仍验证握手签名，证明对端持有证书对应私钥；首次允许自签名证书，必须通过双端安全校验确认建立信任。
5. 两端显示与会话绑定的安全校验码，用户核对一致并分别确认后保存对端证书指纹。请求有超时和数量上限。
6. 后续发送必须验证已保存的指纹；名称和 IP 变化不影响身份，证书变化必须重新配对。
7. 用户可移除信任。未配对或已移除的设备不能收发业务数据。

TLS 的自签名引导与业务授权是两个层次。不能因为 TLS 握手完成，就允许未配对设备传输。安全校验码必须绑定当前 TLS 会话，避免可重放的静态指纹摘要。

## 5. 发现与网络选择

自动发现发布当前实际监听端口，收到服务移除事件后更新列表。多网卡地址逐个尝试，连接后以证书确认身份。发现不可用不影响手动 IP 连接，并在界面提示。

第一阶段仅提供局域网模式。即使没有互联网，也能发现、配对、传输。系统可能要求授予本地网络或防火墙权限。访客 Wi-Fi 的设备隔离、跨 VLAN 和 VPN 路由可能阻止直连；同一 Wi-Fi 不等于必然可达。

后续模式：

| 模式 | 行为 |
| --- | --- |
| 自动 | 验证本地直连可用后优先使用，否则转互联网 |
| 仅局域网 | 禁止公网回退，连接失败提示原因 |
| 仅互联网 | 跳过局域网，选择公网通道 |

网络模块提供经过认证的双向字节流，传输模块不依赖具体通道。通道迁移时先协商已落盘位置，再恢复任务；第一阶段断线明确标记失败并清理未完成文件，不声称支持续传。

## 6. 协议

每条连接先进行 TLS 1.3 握手，再交换带版本的业务消息。一条连接处理一次配对、文字、探活或文件任务，避免复杂多路复用。控制消息采用有界 JSON 帧；文件内容采用有界二进制帧，不使用 Base64。

帧头：1 字节类型、4 字节大端长度。读取长度后先检查上限，再分配内存。文字原始 UTF-8 限制 64 KiB，控制帧限制 512 KiB（容纳 JSON 转义后的文字），文件块限制 256 KiB。读写有超时，连接数和待确认请求有上限。

文字通过消息 ID 去重，只有接收方持久化后才返回成功确认。前端按纯文本渲染，不能将收到的文字作为 HTML 执行。

## 7. 文件传输

```text
选择文件 → 验证源文件 → 发送名称/大小/任务 ID
→ 接收方确认 → 分块读写 → 核对长度和 SHA-256
→ 原子保存且不覆盖已有文件 → 完成确认
```

- 文件格式不参与传输逻辑，内容原样传送；文件夹留待后续。
- 默认每个文件都需要接收方确认，避免可信设备意外占满磁盘。
- 使用有界缓冲、异步 I/O 与背压，内存不随整个文件大小增长。
- 临时文件位于接收目录；拒绝、断线、超时或校验失败后清理临时文件。
- 拒绝路径穿越、绝对路径和控制字符；处理 Windows 不合法字符与保留文件名。
- 同名文件自动加序号，原子提交时也必须防止并发覆盖。
- 接收方校验并完成落盘后返回确认；发送方仅在确认后显示成功。
- 第一阶段传输失败需重新发送。启动时将上次未完成任务标记为中断。

## 8. 界面与本地数据

左侧显示本机信息、发现设备和可信设备；右侧提供目标设备、文字输入、文件选择、接收确认与传输进度。显示当前监听地址、接收目录、发现异常及真实传输状态。

首次配对弹出双方名称、方向、安全校验码和确认/拒绝按钮。历史记录只保存在本机，不代表多端同步。私钥不进入前端、SQLite 或日志。

## 9. 验证与发布边界

- 自动测试：不依赖组播的两节点真实 TCP/TLS 配对、拒绝和超时；未配对禁止传输；证书冒充失败；文字去重；空文件和二进制文件的内容校验；同名文件、恶意名称、断线清理。
- 发现模块单独做组播发布/发现验证，受运行环境网络权限影响时明确报告。
- 构建验证：Rust 测试、格式与静态检查、前端类型检查和构建、Tauri 桌面构建。
- 真实两机验收：Windows/macOS、有线/Wi-Fi、断开互联网、拒绝防火墙权限、设备重启、1 GiB 以上文件和可用磁盘不足。
- 只有本机回环集成测试通过不能宣称跨操作系统两机验收完成。发布前需完成对应平台签名、安装及网络权限验证。

## 10. 后续演进

第二阶段增加公网协调与中继和三种模式；第三阶段增加断点续传与跨通道恢复，再考虑 P2P、文件夹、托盘与离线加密暂存。公网服务需要匿名设备认证、配对尝试限制、会话授权和带宽配额，不能作为开放代理。
