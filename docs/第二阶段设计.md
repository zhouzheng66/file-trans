# 第二阶段：互联网中继与网络模式

> 本文记录该阶段的设计与验收结果。第三阶段已更新文件断线、配额中断和模式切换行为，最新说明见[第三阶段设计](第三阶段设计.md)与[第三阶段验收](第三阶段验收.md)。

## 目标与边界

增加可自行部署的公网协调与中继服务。客户端默认自动优先局域网：本地地址连接并验证身份成功时直传，否则通过同一中继连接。提供仅局域网、仅互联网的手动模式，保存选择。双方必须在线，不增加离线暂存、断点续传或已开始任务的通道迁移。

仓库提供服务与部署配置，不内置未经运营的公共服务地址。用户在两端配置同一个 `wss://` 中继地址；没有配置时，自动模式仍可局域网使用，跨网回退明确提示缺少中继配置。仅本机回环地址允许 `ws://`，用于开发和集成测试。

## 通道与身份

局域网 TCP 和互联网 WebSocket 隧道都承载同一套设备间双向 TLS 1.3。将身份模块的底层流抽象为有界异步字节流；传输和校验协议保持不变。中继只转发内层 TLS 密文，不终止设备间 TLS，不保存文件。外层 WSS 由正常的域名证书保护，不能跳过其证书校验。

客户端维持一个控制 WebSocket，在其上建立双向 TLS，通过证书握手签名证明持有设备私钥，无账号、共享口令或自制签名协议。控制服务的域名身份由外层 WSS 验证，内层服务证书可以在重启后重新生成；设备间数据 TLS 仍固定校验已配对指纹。数据任务使用独立 WebSocket，服务端生成短时、一次性、分双方的随机接入票据。控制连接验证成功不等于业务授权：接收端仍验证设备间 TLS 证书指纹，只接受可信设备的业务连接。

## 跨网首次配对

1. 接收端主动生成临时配对码，五分钟有效；生成新码使旧码失效。
2. 另一端输入该码。中继只匹配在线设备，不提供陌生设备目录。
3. 接收端仅在自己存在对应有效邀请时接受未配对的隧道。
4. 建立内层双向 TLS 后，双方核对会话安全校验码并分别确认，复用第一阶段的信任流程。
5. 后续通过已记住的设备指纹定位；每次连接仍需证书校验，移除信任后拒绝后续连接。

配对码负责找到接收端，不能替代安全校验或直接授予传输权限。中继地址变化后不丢失已有设备身份，但双方必须使用同一个在线协调服务才能跨网连接。

## 路由规则

| 模式 | 新的出站任务 | 新的入站连接 |
| --- | --- | --- |
| 自动 | 有界并发探测局域网候选地址，成功则直连，否则中继 | 接受局域网与获授权的中继 |
| 仅局域网 | 只尝试本地候选地址，失败后报错 | 不连接公网控制服务，不接收新中继任务 |
| 仅互联网 | 直接使用中继，不探测局域网 | 拒绝新的局域网业务连接 |

局域网探测只建立连接并验证身份，不先发送业务内容。只有在业务内容发送前进行回退，避免重复文字和文件。切换模式作用于新连接，已经开始的传输保持原通道直至完成或失败。客户端显示选择的模式、服务连接状态，以及每个任务实际使用的局域网/互联网通道。

## 服务端与可靠性

服务使用 Axum、Tokio 和内存会话表，支持健康检查与优雅退出。控制连接掉线后客户端自动退避重连；在线状态、邀请和待接入会话及时清理。正在传输的数据隧道与控制连接分离，暂时的控制重连不自动中断已有任务。

对 WebSocket 帧、消息长度、连接数、同 IP 连接数、请求频率、会话数量、接入超时、单隧道字节总量和持续时间设置上限。隧道不能指定任意外部主机，只能连接同服务的在线设备，接收端必须同意接入。传输采用有界缓冲和背压。部署默认绑定回环地址，通过 Caddy 的 HTTPS/WSS 入口公开服务。

## 模块与验证

- `crates/relay`：控制协议、经过证明的注册、客户端重连、数据隧道字节流适配。
- `services/relay`：服务入口、会话表、接入与转发、资源限制、部署配置。
- `crates/core`：网络设置持久化、路由选择、跨网邀请配对和任务实际通道记录。
- 桌面界面：模式选择、中继配置、连接状态、配对码与实际通道提示。

通过真实 WebSocket 中继测试跨网逻辑，测试自动优先本地、局域网失败后回退、强制模式、未配对拒绝、错指纹拒绝、邀请失效、掉线重连和端到端文件校验。本机模拟测试与公网部署、两台不同网络电脑的真实验收分开记录。
