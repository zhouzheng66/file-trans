# 互联网中继部署与使用

## 服务作用

中继协调在线设备、匹配短时配对码并转发设备间 TLS 密文。没有账号系统，不提供离线文件暂存。双方必须配置同一个中继地址且同时在线。仓库不内置公共中继地址；需要部署到你能管理的公网服务器。

中继可看到设备指纹、连接 IP、会话和流量规模；文件名、文件内容和文字在设备间 TLS 内传输，中继不解密、不落盘。服务控制连接也要求双向 TLS，设备通过证书私钥证明身份。配对码只用于找设备，首次信任仍需双方核对安全校验码并确认。

## 本机开发验证

```bash
node scripts/rust.mjs run -p file-trans-relay-server
```

默认仅监听 `127.0.0.1:8787`。在同一台电脑的两个独立客户端或联调节点上，设置 `ws://127.0.0.1:8787`。仅回环 IP 允许明文 WebSocket；公网或局域网 IP 必须使用 `wss://`。

健康检查地址为 `http://127.0.0.1:8787/health`。该地址只报告进程可响应，不替代两端完整传输验收。

## 公网 Docker Compose 部署

准备一台 Linux 公网服务器、Docker Compose 和一个解析到该服务器的域名。以下域名仅为示例，需要替换为你自己的域名。确保 HTTPS 入口的 80/443 端口可达。

在仓库根目录运行：

```bash
RELAY_DOMAIN=transfer.example.com docker compose -f services/relay/compose.yaml up -d --build
```

Caddy 负责申请和续期公开可信的 HTTPS 证书，并转发 WebSocket。Rust 服务的 8787 端口没有直接暴露到公网。客户端填写 `wss://transfer.example.com`，不添加 `/control`、`/tunnel`、查询参数或账号密码。

已有反向代理时，可单独运行 Rust 服务并代理 `/control`、`/tunnel` 和 `/health`，需要支持 WebSocket 升级与长连接，不能对数据隧道设置很短的总响应超时。公网 WSS 证书使用正常信任链，不支持跳过验证或强行接受自签名网站证书。

## 客户端操作

1. 两端在顶部“互联网设置与跨网配对”保存同一中继地址，等待“中继已连接”。
2. 接收端点击“生成五分钟配对码”；另一端输入该码并连接。新配对码会替换旧码。
3. 核对两端显示的八位安全校验码一致，再分别确认配对。
4. 此后选择设备发送文字或文件。每个任务显示实际通道。

网络模式：

| 模式 | 行为 |
| --- | --- |
| 自动，默认 | 先验证局域网连接，约三秒探测预算内未成功则转中继 |
| 仅局域网 | 不连接公网控制服务，禁止中继回退 |
| 仅互联网中继 | 跳过局域网直连，文字连接失败时提示错误，文件任务等待网络恢复 |

模式和中继地址保存在本机。第三阶段文件任务在切换时保存断点、重新选路并继续；文字和配对使用新连接时的设置。自动模式在局域网恢复可达后，也会在检查点将活动中继文件切回直连。未配对设备的业务请求、被移除信任的设备及中继转错的设备，都不能绕过设备间证书校验。

`FILE_TRANS_RELAY_URL` 可作为启动时的地址覆盖项，不改变已保存的网络模式。没有此环境变量时使用界面保存的地址。

## 资源上限与运维

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `RELAY_LISTEN` | `127.0.0.1:8787` | 服务监听地址 |
| `RELAY_MAX_DEVICES` | `256` | 同时在线设备数 |
| `RELAY_MAX_SESSIONS` | `64` | 待接入与活动数据隧道总数 |
| `RELAY_MAX_CONNECTIONS_PER_IP` | `32` | 每个来源 IP 的 WebSocket 连接数 |
| `RELAY_MAX_SESSION_BYTES` | `17179869184` | 单隧道双向总流量，含 TLS 开销，约 16 GiB |
| `RELAY_MAX_SESSION_SECONDS` | `7200` | 活动隧道最长持续时间，两小时 |

每个设备最多同时参与四条数据隧道。单 IP 每分钟最多发起 240 次 WebSocket 连接，每个控制连接每分钟最多 120 条请求。接入票据只可使用一次，二十秒未完成双端接入即过期；消息和缓冲区也有长度限制。

反向代理下服务看到的是代理 IP，因此 Compose 将每 IP 并发连接数调整为 128。代码不信任未经验证的 `X-Forwarded-For`。部署在公开互联网时，可根据使用范围在入口补充来源限制或速率限制；大量不同来源的匿名设备仍可能占用总配额，当前服务面向自用设备，不是开放的大规模公共平台。

中继转发会产生公网带宽成本。配额是每条隧道的上限，超额或超时会中断隧道；第三阶段文件任务保留断点并尝试新建隧道接续，所以它不构成每个文件或设备的累计流量上限。需要总量控制时应在部署入口另行实施。网络中断和服务重启后客户端自动重连，已有设备信任不丢失，旧配对码及未接入会话失效；活动文件恢复时只发送剩余内容。源文件和接收端断点须保持完整，主动暂停的任务不会自动恢复。

## 验证边界

本机真实 WebSocket、设备间 TLS、模式切换和自动回退由自动集成测试覆盖。Docker 镜像、证书签发、公网反向代理及不同网络电脑互传，必须在实际部署环境验收；不能把本机回环测试当成公网部署已完成。
