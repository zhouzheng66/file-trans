## 自动检查

```bash
npm run check
npm run build
npm run test:core
npm run check:rust
npm run lint:rust
node scripts/rust.mjs fmt --all -- --check
```

核心集成测试使用两个独立身份、数据库和接收目录，通过真实 TCP 与双向 TLS 连接，避免依赖组播环境。覆盖双端配对、会话校验码一致、拒绝与过期、未知设备和错误证书、移除信任、Unicode 文字、消息去重、多块二进制文件、空文件、同名文件、校验失败、连接中断和临时文件清理。

局域网发现单独运行：

```bash
node scripts/rust.mjs test -p file-trans-discovery -- --ignored --nocapture
```

该检查需要真实组播网络权限，不能因为回环传输测试成功就认为 mDNS 已通过。

## 真实两机测试清单

- [ ] macOS 与 Windows 分别构建并启动。
- [ ] 两端互相出现在“附近的设备”。
- [ ] 禁止组播时仍能通过手动 IP 和端口配对。
- [ ] 两端安全校验码一致；仅一端确认时不能建立信任。
- [ ] 任一端拒绝或等待过期后，都不会新增可信设备。
- [ ] 拔掉路由器外网连接，保留局域网，仍可发现、配对和传输。
- [ ] 中英文、多行、emoji、HTML 字符作为原始文字展示，可一键复制。
- [ ] 传输图片、压缩包、安装包、无扩展名文件和零字节文件，核对 SHA-256。
- [ ] 传输 1 GiB 以上文件，内存不随文件总大小线性增长。
- [ ] 接收方拒绝后不产生正式文件。
- [ ] 同名文件与并发同名传输不会覆盖已有文件。
- [ ] 传输中关闭一端或断网，另一端明确显示失败；未完成文件清理。
- [ ] 接收目录不可写或磁盘不足时明确显示失败。
- [ ] 重启后配对身份、信任和历史保留；未完成任务标记为中断。
- [ ] 移除设备信任后，对端不能继续建立新的业务连接。
- [ ] 系统 Keychain / Credential Manager 权限被拒绝时，不自动重置身份。

## 发布边界

本机双节点测试不替代真实两机验收。Windows 安装包必须在 Windows 环境构建，发布版需要完成对应平台签名与本地网络权限验证。
