# 第四阶段：文件夹传输与系统拖拽

## 交付范围

支持选择文件夹，以及从 Windows 文件资源管理器或 macOS Finder 直接向应用拖入文件、文件夹或混合多选。用户先选择已配对设备，每个顶层文件夹对应一个任务；接收一次确认即可保留其中的子目录、空目录、零字节文件和二进制内容。

文件夹复用第三阶段的任务持久化、分块校验、断点偏移、双方独立暂停、重连与网络切换。传输过程仍优先局域网，必要时回退中继；中继无需识别文件夹格式。

## 文件夹快照与协议

为避免每个小文件建立连接和重复实现一套调度器，发送前在应用数据目录生成一个无压缩、流式写入的目录快照。快照准备完成后不可变，后续修改原文件夹不改变已经准备好的任务。准备期间的修改会检测并报错；准备中暂停后可重新准备，已经开始网络传输的断点不受影响。

快照由格式标识、受限长度的 JSON 清单及清单顺序排列的文件内容组成。清单记录相对路径、文件/目录类型和字节数；全快照 SHA-256 覆盖清单和内容。目录与文件按相对路径排序，恢复时按快照字节偏移续传。进度包含清单开销；本阶段不压缩、不保留权限、所有者、扩展属性或硬链接关系。

文件夹使用独立的第三版文件夹邀请消息，避免旧客户端把快照误存为普通文件。普通文件继续使用第二版文件协议，文字与配对继续兼容；发送和接收文件夹的两端均需升级。

## 落盘与安全

接收端先将快照作为现有可续传临时文件保存，完整校验后再在接收目录的私有隐藏区域中展开。展开使用有界缓冲，校验全部路径及清单后创建内容；只支持普通文件和目录，拒绝符号链接、Windows 重解析点、设备文件、绝对路径、上级路径、重复路径、跨平台不安全名称和大小写冲突。

限制清单大小为 16 MiB、条目数为 100,000、相对路径长度为 1,024 字节、层级为 64，整个快照沿用 8 TiB 上限。超过限制明确报错，不静默跳过条目。

展开完成后采用禁止覆盖的目录重命名提交；同名顶层目录追加序号，不合并、不覆盖已有目录。提交前保存路径计划，重启后重新核对最终目录的结构与内容摘要，修复完成确认丢失或状态未落库的窗口。展开中暂停、退出或出错会保留完整快照，下次重新展开，无需重复网络传输。取消只删除受管理的快照与展开临时目录，不删除正式接收目录。

## 资源与生命周期

发送端需要约一份文件夹内容的额外磁盘空间保存快照；接收端在展开和提交期间需要约两份内容空间。内存受清单上限与固定数据块约束，不把全部文件内容读入内存。磁盘空间不足会明确失败并保留可重试状态。

发送快照在完成、拒绝或取消后清理，暂停或失败时保留以供恢复。应用重启恢复相同快照，不重新扫描源目录。接收端完成后清理快照，完成重复请求通过最终目录摘要幂等确认。

准备阶段使用带专用前缀的临时文件；启动时在调度任务前回收未被任何持久化任务引用的受管理缓存，避免准备过程中崩溃留下无主快照。

## 界面与模块

- 新增“选择文件夹”，文件与文件夹使用不同图标和接收提示。
- 系统拖拽使用 Tauri 原生路径事件，后端识别路径类型；混合多选逐个创建任务，错误明确展示，不静默只取前四项。
- `folders/manifest` 负责目录扫描、清单验证和路径规则。
- `folders/archive` 负责快照编码、校验与安全展开。
- `folders/prepare` 负责发送准备、暂停检查与快照生命周期。
- `folders/commit` 负责接收展开、禁止覆盖的提交和完成恢复。
- 原有 `transfers` 负责数据传输、断点与路由，不复制一套文件夹网络状态机。

## 验收要求

验证嵌套目录、空目录、零字节与中文名称、同名目录不覆盖；在非零断点暂停、断网、双端重启、切换局域网/中继后继续，同一任务最终目录与快照内容一致。验证恶意路径、链接、冲突条目和损坏快照不会写出接收目录；取消清理临时数据。桌面需验证选择文件夹和外部拖拽入口，并区分本机验证与 Windows/公网实机验证。
