## macOS 桌面验证

通过仅监听回环地址的中继、限速代理和临时联调节点，使用生成的 32 MiB 二进制样例，在原生客户端中实际操作：

1. 核对两端安全码并按用户授权临时配对；收到样例文字与文件接收请求。
2. 接收文件，在已有进度后点击暂停；磁盘保存 24,117,248 字节，界面稳定显示已暂停、23 MiB / 32 MiB。
3. 点击恢复，同一任务显示“已从 23 MiB 断点继续”，随后显示已完成。
4. 最终文件为 33,554,432 字节，SHA-256 为 `83ee47245398adee79bd9c0a8bc57b821e92aba10f5f9ade8a5d1fae4d8c4302`，与生成样例一致；仅有一份正式文件，没有残留 `.part`。
5. 移除本次临时节点信任，清空测试中继地址，保持自动模式，恢复原接收目录并停止测试进程。

此项是本机中继桌面交互验收；公网传输、物理断网和跨平台实机清单仍需在相应环境执行。

## 自动测试覆盖

`crates/core/tests/resume_flow.rs`：

- 发送端在非零断点暂停，恢复后仅发送剩余内容，保存文件一致。
- 活动连接被关闭、网络恢复后，同一任务自动接续，不重复要求接收确认。
- 同一活动文件从局域网切中继，再切回局域网，偏移持续保留。
- 双端引擎关闭、重新启动，保留双方各自的暂停状态；仅恢复一方不能解除另一方暂停。
- 源文件变更和接收断点损坏时拒绝拼接；取消清理受管理的临时文件。
- 中继服务在传输中重启，客户端自动重连续传。
- 自动模式中，活动局域网失效后回退中继。
- 自动模式中，活动中继任务在局域网重新可达后切回直连。

`crates/core/tests/resume_wire.rs`：

- 完成确认丢失后重试不重复保存；模拟正式文件已提交而完成状态尚未落库的崩溃窗口，重启后修复完成状态。
- 拒绝错误块偏移，取消后清理断点。
- 控制通知乱序时，旧暂停消息不能覆盖较新的恢复消息。

第一、二阶段的文字、配对、设备信任、文件名处理、不覆盖同名文件、异常文件、邀请、隧道票据和强制网络模式回归测试也通过。中继配额测试已更新为检查断点保留、等待重连及主动取消清理。

## 两机实测清单

两端均升级客户端，并在每个任务中记录任务 ID、偏移和实际通道。跨网测试需先按[中继部署](中继部署.md)配置可用的公网 WSS 服务。

- [ ] Windows ↔ macOS 双向传输零字节、无扩展名、重名、常见二进制和大于 1 GiB 文件，最终 SHA-256 一致。
- [ ] 文件收到非零进度后，分别在发送端和接收端暂停；进度停止并保留，恢复后同一任务完成。
- [ ] 双方分别暂停，单端恢复后仍保持另一端暂停；双方恢复后继续。
- [ ] 传输中关闭 Wi-Fi 或拔网线，再恢复网络；接收方不重复确认，断点继续。
- [ ] 分别退出、重开两端应用，用户暂停保持暂停，其余任务自动恢复。
- [ ] 传输中切换仅局域网、仅互联网和自动，实际通道正确且从非零断点继续。
- [ ] 自动模式下局域网中断后使用中继，局域网恢复后活动文件回到直连；双方选择互不兼容的强制模式时等待重连。
- [ ] 中继或反向代理重启、连接超时、单隧道额度耗尽后可新建连接接续。
- [ ] 磁盘空间不足、接收目录不可写、源文件被移动或修改时错误清晰；问题解决后恢复或取消重发。
- [ ] 取消不会删除已有正式文件；断网时对端通知失败的残留任务可在对端独立取消。

## 使用限制

已保存前缀在恢复时需要本地重新读取校验，大文件可能有一段校验等待时间；网络不重复发送该前缀。发送源文件须保留原路径且不变，接收端隐藏断点目录也须保留。修改默认接收目录不迁移已有任务。新文件任务要求两端支持第二版文件协议；旧阶段的失败记录不会自动转为续传任务。
