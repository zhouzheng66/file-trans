# 第三阶段：断点续传、暂停恢复与通道迁移

> 第四阶段已在本阶段任务引擎上增加文件夹快照与系统拖拽，文件夹准备和落盘细节见[第四阶段设计](第四阶段设计.md)。

## 目标与协议边界

文件传输升级为持久化任务，支持任一端暂停、恢复、取消，自动等待网络恢复，以及应用重启后继续未完成任务。切换全局网络模式会让进行中的文件保存断点、重新选路并续传。自动模式中，局域网失效后回退中继；长时间使用中继时定期在检查点探测局域网，恢复可达后切回直连。

文字、配对与旧版文件协议保持兼容。新任务使用独立的第二版文件消息，两端需使用支持第三阶段的客户端。旧版失败记录不会被悄悄重新发送。中继继续只转发 TLS 密文，无需理解新文件协议。

## 文件身份与断点协议

任务由发送端设备指纹、接收端设备指纹和随机 UUID 唯一标识，数据库按对端、方向和 UUID 隔离。首次准备计算源文件大小、修改时间和全文件 SHA-256，元数据变化或最终哈希不一致时明确报错，不把不同版本拼接。

1. 发送方提交文件身份与任务 ID；接收方首次确认后记住授权，重连不重复弹出接收提示。
2. 接收方返回持久化偏移和前缀 SHA-256。双方重新检查本地文件前缀，一致后才从该位置继续。
3. 文件按不超过 256 KiB 的数据块传输，每块包含偏移、长度和 SHA-256，拒绝错位、重复和损坏数据。
4. 每个不超过 4 MiB 的窗口确认一次。接收方先写入并同步磁盘，再原子提交 SQLite 断点，最后返回确认。
5. 暂停、迁移或连接中断时，接收方尽量同步已经完整收到并校验通过的数据块。未收完整的帧不写入文件。
6. 全文件长度和 SHA-256 一致后才提交正式文件。完成确认丢失时，同一任务重试返回已完成，不生成第二份文件。

恢复需要本地读取已确认前缀进行校验，不会把该前缀再次从网络发送。临时文件丢失或损坏时明确报错，不声称能够无条件恢复缺失数据。源文件仍须保留在原路径。

## 持久化与文件安全

SQLite 新增任务表，将任务元数据、用户暂停标记、对端暂停标记、断点、接收授权、实际通道和历史状态在同一事务中保存。进度不能覆盖并发的暂停/取消决定。启动时恢复未完成任务，用户主动暂停的任务保持暂停。

接收临时文件保存在首次选择接收目录的隐藏子目录，目录按本机身份隔离，文件名由可信设备指纹和 UUID 生成。重连接收使用任务级独占锁，避免旧、新通道同时写文件。修改默认接收目录不迁移已有任务。

正式保存仍不覆盖同名文件。提交前记录最终路径计划；如果在文件提交后、数据库完成状态保存前崩溃，重连时核对最终文件后补齐完成状态。取消清理本机受管理的临时文件，已完成文件不会被取消操作删除。对端离线时，控制通知可能无法送达，对端可独立取消其保留的断点。

## 控制与路由

用户暂停和对端暂停分别保存，恢复一端不会解除另一端的主动暂停。控制通知携带持久化递增序号，忽略迟到的旧通知，避免快速暂停/恢复时被乱序消息覆盖。控制通知通过经过身份校验的连接传递，断网时本地决定立即生效；对端暂停状态在后续握手中再次协商。

发送任务负责重连；接收端等待新的文件会话。网络错误进入等待重连并退避重试，不从零新建任务。接收端暂停后，即使控制通知丢失，也会通过文件握手拒绝继续写入；恢复通知唤醒发送端，另有有界间隔探测兜底。源文件错误、磁盘错误、断点损坏、拒绝和取消与网络暂时不可用分别显示。

三种模式保持第二阶段的约束：仅局域网禁止中继，仅互联网模式禁止直连，两端模式没有兼容路径时等待重连。切换模式或中继地址使活动任务从安全断点重新握手。后台探测只对自动模式的中继任务进行，不会违反手动模式。

## 模块设计

- `transfers/model`：任务、文件身份、断点和方向模型。
- `transfers/runtime`：任务控制通知、接收锁、后台任务生命周期。
- `transfers/source`：源文件准备、变更检测与前缀校验。
- `transfers/control`：暂停、恢复、取消和对端控制通知。
- `transfers/handshake`：接收授权、断点协商和完成重试。
- `transfers/wire`：消息超时与耗时本地校验期间的保活。
- `transfers/partial`：断点文件、落盘确认和安全提交。
- `transfers/sender`：发送、窗口确认、重试与迁移。
- `transfers/receiver`：接收授权、偏移验证、落盘和完成幂等。
- `storage/transfers`：任务与历史的事务持久化。
- 桌面界面：暂停、恢复、取消、等待重连、续传起点和实际通道。

旧版文字与文件兼容处理不与新任务调度混在一个长文件中。

## 验证要求

通过真实 TCP/TLS 和 WebSocket 中继测试：收到非零断点后暂停并恢复、接收端暂停、双方分别暂停、源/接收进程重启恢复、断网与中继重启恢复、传输中局域网与中继双向迁移、错偏移/哈希拒绝、断点损坏、源文件变化、完成确认丢失重试不重复落盘、取消清理和旧协议回归。验证续传起点大于零且最终内容一致，不能只验证最后状态显示完成。
