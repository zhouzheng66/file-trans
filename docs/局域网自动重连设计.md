# 局域网自动发现与重连

## 问题

已配对设备保存的是某次连接的 `IP:端口`，监听端口由系统动态分配，设备重启后可能变化。原实现只在发起连接时读取一次发现快照；组播广播晚到、休眠或网络切换后发现状态没有及时刷新时，会持续尝试旧地址。连接新地址成功后也没有更新持久记录，因此应用再次启动时还会回到旧地址。

macOS 还有应用级本地网络权限。系统工具能够解析服务和连接端口，并不代表应用的原始 UDP 组播套接字也具有相同权限。

## 模块与流程

- `crates/discovery/src/lib.rs` 负责广播、发现缓存和地址变化订阅。每 10 秒主动重新浏览服务；按需查询请求在一秒内合并，保留现有缓存。针对已知设备主动验证 SRV 和地址记录。
- `crates/discovery/src/macos.rs` 通过系统 `DNSServiceResolve` 解析已配对设备的确定性服务名，再通过系统主机解析取得 IPv4 地址。解析不依赖原始 UDP 发现结果；设备 TXT 标识和协议版本须匹配。系统拒绝本地网络访问时返回明确的权限提示。解析引用、回调上下文和文件描述符由同一对象管理，future 取消时释放。
- `crates/core/src/engine/lan.rs` 负责后台刷新已配对设备以及动态连接。连接前先订阅地址更新，同时尝试发现地址和历史地址；连接过程中到达的新地址也参加尝试。并发上限为 4，总预算为 5 秒，单地址预算为 2 秒，一轮最多尝试 32 个地址。失败信息保留具体地址和解析原因。
- `crates/core/src/storage.rs` 仅在固定设备指纹的 TLS 握手成功后更新保存地址。更新只修改现有配对记录，不新增记录，防止重新建立已删除的信任。
- `apps/desktop/src/components/DeviceMenu.tsx` 提供设备列表右侧的“⋯ → 删除设备”菜单。删除前复用确认对话框和 `forget_peer` 命令；已有文件与历史记录保留，再次收发需要重新配对。支持键盘打开、Escape 关闭和点击外部关闭。

文件任务继续复用已有等待重试、断点续传和暂停控制。每轮重试读取最新地址，因此接收端重新上线后无需手动添加地址。后台刷新不发送业务内容；仅互联网模式不执行已配对设备的主动局域网解析。后台任务响应退出取消并在关闭时等待结束。

## 安全与边界

广播及系统解析结果只提供连接候选地址，不能授予信任。全部业务连接仍固定校验首次配对的 TLS 设备指纹；错误设备不得更新持久地址。首次配对仍需双方确认。

自动重连要求目标客户端正在运行、网络允许设备互通、应用已获得系统本地网络权限。该修复不会绕过系统权限或网络隔离。macOS 正式发行仍应使用稳定的 Developer ID 签名。

## 验证

默认测试覆盖连接期间收到新端口、旧端口仍接受 TCP 但不完成 TLS、验证后持久化新地址、发送端重启后直接发送，以及伪造发现不能覆盖地址或恢复已撤销信任。发现模块测试还覆盖 IP 与端口更新、避免重复设备和冗余通知、TXT 解析及截断数据处理。

真实网络测试独立运行：

```sh
node scripts/rust.mjs test -p file-trans-discovery -- --ignored --test-threads=1
node scripts/rust.mjs test -p file-trans-core --test lan_rediscovery -- --ignored --test-threads=1
```

第二条通过真实发现连接两个本机节点：配对一次，接收端关闭并换端口，等待中的文件自动完成并校验内容，再重启发送端确认仍能发送，不修改配对地址、不重新配对。它验证本机 TCP/TLS、组播和 macOS 系统 Bonjour，不代表已完成 Windows/macOS 两台物理电脑的升级验收。
