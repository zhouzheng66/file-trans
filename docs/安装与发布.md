# 各平台安装包与发布流程

## 下载与安装

从仓库的 [GitHub Releases](https://github.com/zhouzheng66/file-trans/releases) 下载与你的系统、处理器匹配的安装包。每个安装包旁都有 SHA-256 校验文件，JSON 文件记录源码提交及目标架构。

| 系统 | 架构 | 格式 | 说明 |
| --- | --- | --- | --- |
| Windows | x64 | NSIS `.exe` | 运行安装程序，需要 WebView2 |
| macOS | Apple 芯片 arm64 | `.dmg` | 打开磁盘映像，将应用复制到 Applications |
| macOS | Intel x64 | `.dmg` | 与 Apple 芯片版本分别构建 |
| Linux | x64 | `.deb`、`.AppImage` | 基于 Ubuntu 22.04，需图形桌面和 Secret Service |

Windows ARM64 和 Linux ARM64 暂未提供原生包。Windows 安装包目前无发行者证书签名；macOS 从 v0.2.4 起对完整应用包执行临时签名（ad-hoc），但没有 Developer ID 发行者签名或 Apple 公证。临时签名与 SHA-256 校验用于检查内容完整性，不替代发行者身份认证，系统首次打开仍可能要求用户确认。

Linux 的设备私钥通过 Secret Service 保存，需要会话 D-Bus 和解锁的凭据库（例如 GNOME Keyring）。`.deb` 可使用 `sudo apt install ./安装包.deb` 安装并解析依赖；AppImage 需要可用的系统 WebKitGTK 4.1、GTK3、D-Bus 与运行支持。无桌面的 Linux 服务器应使用中继服务，不运行桌面客户端。

## 构建与版本

`Desktop Installers` 工作流在推送 `main` 或 `v*` 标签时构建四个目标；也可在 Actions 手动启动。分支构建只生成安装包产物，产物保留 30 天；成功的标签构建另存到 GitHub Release。

1. 同步根目录及桌面 npm 包、Cargo workspace、Tauri 配置中的版本，并更新两份锁文件。
2. 在 `docs/releases/v版本.md` 编写中文发布说明。
3. 运行 `node scripts/release-version.mjs` 与已有检查，提交源码。
4. 创建匹配版本的 Git 标签并推送，例如 `git tag -a v0.2.0 -m 'File Trans v0.2.0'` 后推送该标签。
5. 等待源码验证、四个目标打包全部成功，工作流才发布 Release；任何失败都会阻止发布。修复代码使用新的提交和版本标签，不移动已发布标签。

macOS 两个目标在 macOS 构建，配置 `bundle.macOS.signingIdentity` 为 `-`，打包后由 `scripts/verify-macos-dmg.mjs` 只读挂载最终 DMG，确认其中应用通过 `codesign --verify --deep --strict`，版本与目标架构也须匹配；缺少完整资源封印时构建失败，不再发布只有链接器临时签名的应用。Windows 在 Windows 构建，Linux 在 Ubuntu 构建。`scripts/collect-installers.mjs` 验证预期格式均已生成、统一命名，并流式计算 SHA-256。Linux 验证步骤还在独立 D-Bus 与 GNOME Keyring 会话中确认同一设备身份跨进程可读取。

流程参考 [Tauri GitHub Actions](https://v2.tauri.app/distribute/pipelines/github/)；凭据库采用 [keyring-rs](https://github.com/open-source-cooperative/keyring-rs/tree/v3.6.3) 的系统后端。构建日志不打印私钥或访问令牌。
