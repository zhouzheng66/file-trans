# 收发交互设计

## 文字发送

输入框按 Enter 发送，Shift + Enter 换行，保留 Ctrl / ⌘ + Enter 发送。正在使用输入法组合文字或确认候选词时，Enter 由输入法处理；同时检查原生组合状态和 WebKit 的 229 按键码。按键自动重复不触发第二次发送。空白内容与正在发送的内容不能重复提交，失败保留输入，发送期间的新输入不会被成功回调清空。

## 自动接收

桌面启动时启用引擎的 `auto_accept_files` 策略，对通过 TLS 指纹验证的已配对设备自动接收普通文件、文件夹与兼容旧协议的文件。首次配对仍需双方核对安全码，未配对或移除信任的设备不能发起传输。

策略位于 Rust 接收握手中，不依赖前端是否选中对应设备、是否打开会话或是否轮询。接收授权在创建任务时持久化，再沿用原有断点、暂停、重连、通道迁移和完整性校验流程。升级后未确认的旧任务自动转为等待连接；用户暂停状态保持，已取消、拒绝、失败的任务不会因自动接收而复活。旧任务所属设备已移除信任时，不自动授权，也不阻止应用启动。

界面移除逐项接收／拒绝按钮和待确认提示，继续提供暂停、恢复、取消。核心库保留手动确认能力及现有接口，默认关闭自动接收；桌面入口明确启用，便于兼容已有调用方与测试手动授权路径。

## 接收目录

独立的 `ReceiveDirectory` 组件显示当前目录和“修改目录”按钮，原生目录选择器从当前目录打开。后端要求绝对路径，创建目录并用自动清理的临时文件验证可写，验证成功后才保存 SQLite 设置；失败保持原设置并显示错误。应用重启优先读取已保存设置。

新接收任务在创建时固定目的目录。修改默认目录只影响后续任务，不移动正在传输或已暂停的数据，避免断点与目录快照失配。文件和文件夹仍使用同名另存，完整性校验后才提交到最终位置。

## 定位接收内容

已完成的接收文件和文件夹显示“打开所在位置”。前端只传任务 ID 和对端 ID；原生命令从本地完成记录取路径，检查内容仍存在，再调用 [Tauri Opener](https://v2.tauri.app/plugin/opener/) 的文件管理器定位能力。前端不获任意文件打开或执行权限。

macOS 在 Finder 中定位并选中，Windows 使用文件资源管理器，Linux 使用系统文件管理器服务，定位服务不可用时回退为打开所在目录；实际选中效果取决于桌面文件管理器的实现。文件被移动、删除或文件管理器调用失败时，界面显示错误。该操作不执行收到的文件。

## 验证范围

集成测试使用真实 TCP/TLS 和 WebSocket 中继，覆盖无需确认的文件与目录接收、空目录与中文名称、同名另存、目录设置持久化及无效路径回退；传输中修改目录后暂停、重启、切换中继，验证断点大于零且继续写入原目录；另验证旧协议自动接收及未知／撤销信任设备不能发送。现有手动确认与断点续传测试继续保留。
